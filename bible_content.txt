Part 1: Objective and Success Criteria
1.1  Agent Objective
Project Apex deploys an off-policy Soft Actor-Critic (SAC) reinforcement learning agent to manage a long-only equity portfolio drawn from the Nasdaq-100 (NDX) universe. The agent rebalances weekly and optimizes risk-adjusted excess return over the QQQ benchmark.
The RL objective is to maximize expected cumulative discounted reward:
J(╧Ç)  =  E_{╧ä ~ ╧Ç}  [  ╬ú_{t=0}^{T}  ╬│^t ┬╖ r_t  ]
where:  r_t = per-step reward at week t  (see Part 6 for full definition)
        ╬│   = discount factor            (value 0.975)
        ╧Ç   = stochastic portfolio policy (actor)
        ╧ä   = trajectory sampled from the environment under ╧Ç
Maximizing J(╧Ç) operationally corresponds to:
Generating positive weekly excess returns over QQQ (benchmark-relative performance)
Penalizing downside volatility relative to the QQQ return via the risk-shaping term in r_t
Implicitly managing turnover costs, since costs reduce the net return embedded in r_t
1.2  Success Criteria
A strategy passes evaluation when ALL of the following hold across the out-of-sample (OOS) walk-forward folds:
Statistical significance definition: the lower bound of the 95% moving block bootstrap confidence interval on the full concatenated OOS excess CAGR series is strictly above zero, AND the Sortino ratio CI ideally exceeds QQQ's Sortino ratio.
1.3  Non-Negotiable Constraints
The following portfolio constraints are enforced by the deterministic ConstraintProjector at every rebalance step. They cannot be violated in any portfolio submitted for reward computation or evaluation:
Long-only: w_exec_i ΓëÑ 0  for all i Γêê {1, ..., K_max}
Full investment: ╬ú_i w_exec_i = 1.0  (no cash allowance unless full infeasibility ΓÇö see ┬º5.7)
Per-name cap: w_exec_i Γëñ per_name_cap  for all active i  
Sector cap: ╬ú_{i Γêê sector_s} w_exec_i Γëñ sector_cap  for each GICS sector s  
Non-member exposure: any asset not in NDX at the rebalance date must have w_exec_i = 0.0
[DESIGN NOTE]  Hard constraints are enforced by the deterministic projection step ΓÇö not via soft penalty terms in the reward. This guarantees feasibility at every time step without requiring the agent to learn constraint satisfaction. The agent observes the post-projection executed weights (w_exec) and receives gradient signal through them. An optional soft diagnostic penalty for proximity to caps may be logged but does not enter the reward used for training.
Part 2: Data Pipeline
2.1  Raw Data Sources and Schemas
2.1.1  Daily Price Bars  ΓÇö  daily_bars.parquet
All price columns contain total-return adjusted values (dividends and splits reflected). This is the only price type used anywhere in Project Apex for return calculation, feature engineering, portfolio NAV evolution, and execution price estimation.
All per-asset prices are adjusted using CRSP's cumulative adjustment factor: 
adj_close = PRC / CFACPR. 
This accounts for both stock splits and cash dividends (total return basis). Per-asset and benchmark returns are computed as log returns: 
r_{i,t} = ln(adj_close_{i,t} / adj_close_{i,tΓêÆ1}). 
Log returns are used throughout for time-additivity in rolling window computations and approximate normality in volatility estimation
2.1.2  NDX Membership Snapshots  ΓÇö  ndx_membership.parquet
Membership snapshots must represent point-in-time data: the snapshot valid on date d contains only the tickers that were actually in the NDX on date d. No future membership information is ever accessible at or before date d (as-of rule ΓÇö ┬º2.5).
2.2  Calendar and Timestamp Conventions
The rebalance date for week t is the first trading day of that calendar week.
The trading calendar is precomputed over the full data range and stored as a canonical list of trading days.
Every date is mapped to an integer time index t_idx via a precomputed lookup: t_idx = date_to_tidx[d].
All arrays (bars, features, membership) are indexed by t_idx rather than by raw date to avoid calendar-edge bugs.
Decision time: close of rebalance date d_t  (observation is formed using data available at close of d_t).
Execution time: open of d_{t+1}  (the first trading day after d_t; trades fill at this open price).
NAV is marked close-to-close: the portfolio return during week t is measured from the adjusted close of d_t to the adjusted close of d_{t+1}.
2.3  Ticker Vocabulary and Security ID Mapping
All data is keyed by permanent security_id rather than by ticker symbol. This ensures continuity across corporate events:
Ticker symbol changes (e.g., GOOGL ΓåÆ GOOG, Facebook ΓåÆ Meta): the security_id remains constant; a ticker alias table maps all historical tickers to their security_id.
The ticker alias table is a static lookup file maintained alongside daily_bars.parquet.
K_max is the maximum number of securities that can appear in the padded observation tensor. It must be sized to accommodate the maximum historical NDX membership count plus a buffer.
A canonical security_id ΓåÆ tensor index mapping is fixed for each training fold. New tickers that appear after the mapping is created are assigned indices up to K_max.
[DESIGN NOTE]  Using security_id rather than ticker prevents look-ahead leakage from name reuse and ensures embeddings are semantically stable across corporate events.
2.4  Data Validation, Missingness Rules, and Tradability
2.4.1  Tradability Definition
An asset i is tradeable at rebalance date d_t if and only if ALL of the following hold:
Asset i is a current NDX constituent per the snapshot valid on d_t
Asset i has a valid (non-NaN, non-zero) adjusted close price on d_t
Asset i has a valid adjusted open price on d_{t+1} (the execution date)
Tradability is a hard gate: it directly controls the mask_t vector. Any asset with mask_t[i] = 0 receives w_exec_i = 0 always.
 Missingness Handling
Short-term missingness (data gap Γëñ allowed duration [see 5.7]): freeze the previous executed position. The asset is treated as active with its last known price used for NAV marking.
Prolonged missingness (data gap > threshold): the asset is treated as non-tradeable and scheduled for forced liquidation at the next rebalance.
If missing data prevents forming a valid observation window for an episode, the episode terminates.
2.5  Membership Representation and the As-Of Rule
The as-of rule is the central anti-leakage mechanism for universe construction:
At decision time t with rebalance date d_t, the environment uses only the NDX membership snapshot whose effective date is Γëñ d_t.
The snapshot used is the most recent one with effective_date Γëñ d_t. No future additions or deletions are visible.
Membership snapshots are stored with their exact effective dates; any interpolation must use backward fill (carry the last known snapshot forward), never forward fill.
[DESIGN NOTE]  The as-of rule eliminates survivorship bias by ensuring the agent never knows in advance which tickers will be added to or removed from the NDX. This is enforced at the data pipeline level so it cannot be accidentally violated at the feature or environment level.
2.6  Liquidation and Forced-Sell Policy
Any asset that exits the NDX or becomes non-tradeable triggers a forced liquidation.
The forced liquidation is executed at the open of d_{t+1} (the execution date immediately following the decision date on which the removal is detected).
Forced-liquidation trades incur the full transaction cost model (┬º5.4), including commission and market impact.
The freed NAV is redistributed to other active positions according to the projection result (w_exec) for that step.
For delistings specifically: the final available adjusted close is used as the liquidation price. The asset is then removed from all future observations and the mask.
[DESIGN NOTE]  Forced liquidation at next-open prices ensures no look-ahead. The cost model is applied to forced sells to accurately reflect the true economic cost of index membership changes.
2.7  Look-Ahead Leakage Prevention
The following rules prevent any future data from contaminating training or feature computation:
All per-asset time-series features are computed using only data with index Γëñ t_idx. No feature for week t may use any data from week t+1 onward.
All normalizer statistics (running mean, running std) are computed causally: only past data available up to t_idx is used. No future statistics are used for normalization.
Walk-forward fold boundaries enforce a hard embargo between training and test periods (┬º9.1). embargo_weeks = 4 (= n_step = 4 weeks).
Membership snapshots are accessed using the as-of rule (┬º2.5) with backward fill only.
Look-ahead trap tests (┬º11.3) must be run after every data pipeline change to verify no leakage.
Exact purged/dropped dates per fold are logged in the fold metadata (┬º10.3).
Part 3: Feature Engineering
3.1  Per-Asset Time-Series Features
For each active asset i at time t, a feature vector of length F is computed over the lookback window L (in weeks). These features are stacked to form the per-asset history block x_t[i] Γêê R^{L ├ù F}.
Confirmed feature categories from the SoT:
Return features: rolling weekly returns at multiple horizons (e.g., 1-week, 4-week, 13-week, 26-week, 52-week). Each is a log-return or simple return computed from adjusted close prices.
Momentum features: medium- and long-term momentum signals derived from rolling cumulative returns, potentially excluding the most recent week (skip-1 momentum convention).
Volatility features: rolling realized volatility (standard deviation of log-returns) computed over windows of varying length.
Volume features: normalized volume or volume ratio (asset volume relative to its own rolling average) as a proxy for liquidity.
Drawdown features: rolling maximum drawdown from recent peak.
RSI-type features: relative strength indicators or mean-reversion signals at short horizons.
3.1.1  Per-Asset Time-Series Features List
3.2  Cross-Sectional Features
At each time t, cross-sectional features are computed by ranking or z-scoring per-asset features relative to the current active universe of K_active tradeable assets.
Cross-sectional z-scores: for each per-asset feature f, compute z_i = (f_i - mean_cross) / std_cross where the mean and std are taken across all active assets at t.
Cross-sectional ranks: normalized rank of each asset's feature within the active universe (rank Γêê [0,1]).
[DESIGN NOTE]  Cross-sectional normalization ensures feature scales are relative to the current universe composition rather than absolute levels. This makes the features more robust to regime changes and index membership turnover.
3.2.1  Cross-Sectional Features List
3.3  Macro / Broadcast Features
Macro features are shared across all assets at time t and are broadcast into the global context vector g_t rather than the per-asset feature block x_t.
VIX (CBOE Volatility Index): current level and recent change; proxy for market regime.
Yield curve features: level and slope of the US Treasury yield curve (e.g., 2Y-10Y spread, 10Y level); proxy for macro conditions.
3.3.1  Macro/Broadcast Features List
3.4  Portfolio-State Features
Portfolio-state features capture the agent's current portfolio position and performance state. They are included in the global context vector g_t.
Current executed weights w_exec_{t-1}: the portfolio weight vector from the previous rebalance.
Unrealized P&L per asset: normalized gain/loss on each current position since entry.
Rolling drawdown: current drawdown of portfolio NAV from its recent peak.
Rolling turnover statistics: recent average turnover (proxy for recent trading intensity).

3.5  Benchmark Features
QQQ benchmark features are included in the global context vector g_t to give the agent awareness of benchmark performance:
QQQ weekly return over the last L weeks (as a scalar or short time-series).
QQQ rolling volatility.
Excess return of portfolio vs QQQ over recent rolling window (performance attribution context).

3.6  Normalization Strategy
All features are normalized before entering the observation tensor. Normalization must be causal (no future statistics) and consistent across training and inference.
3.6.1  Per-Asset Normalization
Running per-asset statistics (mean, std) computed causally over a sliding window of norm_window_weeks (52) of recent data.
Applied independently per asset: z_i = (f_i - running_mean_i) / (running_std_i + ╬╡).
Features with structural scale differences (e.g., price levels vs. returns) use separate normalization statistics.
3.6.2  Cross-Sectional Normalization
Applied after per-asset normalization for features in ┬º3.2.
Uses cross-sectional mean and std computed at each time t from the active K_active assets.
3.6.3  Global (Fixed-Scale) Normalization
For macro features with well-defined scales (e.g., VIX, yield spreads), a fixed normalization based on long-term historical statistics may be used.
3.6.4  Clipping
After normalization, all features are clipped to [-norm_clip_threshold, +norm_clip_threshold] to limit outlier influence. 
[DESIGN NOTE]  Causal normalization statistics prevent look-ahead leakage during both training and evaluation. The same normalization statistics computed on the training period must be used (or carried forward) during OOS evaluation without refitting.
Part 4: Observation and Action Space
4.1  Observation Tensor Specification
The full observation at timestep t consists of two components:
x_t  (per-asset block):  shape [L, K_max, F],  dtype float32.  Contains the L-week normalized feature history for all K_max padded asset slots. Inactive slots (mask_t[i]=0) are zero-padded.
g_t  (global context vector):  shape [D_global],  dtype float32.  Concatenation of portfolio-state features, benchmark features, and macro features. [20: D_global dimension]
The combined observation s_t = (x_t, g_t, mask_t) is the full information set available to the agent at decision time t.
4.2  Active ID and Mask Specification
mask_t[i] = 1.0  iff  asset i is tradeable at time t (in NDX + has valid price data).
mask_t[i] = 0.0  for all inactive, padded, or non-member slots.
active_ids_t contains the security_id indices for all K_active active slots, padded with sentinel value ΓêÆ1 for slots beyond K_active.
K_active = ╬ú_i mask_t[i]  (integer count of tradeable assets at time t).
The mask is applied before softmax in the actor (masking invalid logits to ΓêÆΓê₧), ensuring w_pre_i = 0 for all inactive i.
4.3  Padding and Batching Strategy for Variable K
Because the active universe size K_active varies week-to-week (assets join/leave NDX), all tensors are padded to the fixed dimension K_max:
Observation slots for inactive assets are zero-padded to K_max.
Action vectors (w_pre, w_exec) are zero-padded to K_max.
Mask vectors (mask_t) are stored in the replay buffer padded to K_max.
When sampling a batch of B transitions from replay, all tensors have consistent shape [B, L, K_max, F] and [B, K_max] because of this padding.
The mask is propagated through every network component to prevent gradient flow through inactive slots (see ┬º7.5 for attention masking).
4.4  Action Space Definition
The action space is a continuous distribution over portfolio weight vectors subject to the feasibility constraints in ┬º1.3. The full action generation pipeline at each step is:
Step 1:  logits_t = ActorHead(asset_repr_t, g_t)                   // shape [K_max]
Step 2:  logits_t[mask_t == 0] = -1e9                              // mask inactive slots
Step 3:  noise = Logistic-Normal(0, ╧â_noise) shape [K_max]         // stochastic exploration
Step 4:  logits_t = logits_t + noise                               // inject noise in logit space
Step 5:  logits_t[mask_t == 0] = -1e9                              // re-apply mask after noise
Step 6:  w_pre = softmax(logits_t)                                 // shape [K_max]; pre-projection weights
Step 7:  log_pi_pre = log_prob(w_pre | logits_pre_distribution)    // for SAC entropy computation
Step 8:  w_exec = ConstraintProjector(w_pre, mask_t)               // post-projection executed weights
╧â_noise: actor learns exploration scale directly via a log-standard-deviation head
At each step, actor outputs: ╬╝ (mean logits), log_std (per-asset)
log_std Γêê [-5, 1]
╧â = exp(log_std)
Initialization: log_std=ΓêÆ1.5(╧âΓëê0.22)
4.5  Constraint Projection
The ConstraintProjector maps any w_pre to a feasible w_exec satisfying all constraints in ┬º1.3. Properties:
Algorithm: deterministic Euclidean projection onto the feasibility set (intersection of: simplex, long-only box, per-name box, sector polytope).
The projection is differentiable with respect to w_pre, allowing gradients to flow back through the projection to the actor during training.
Non-tradeable assets (mask_t[i]=0) are forced to w_exec_i = 0 before projection by zeroing both logits and pre-projection weights.
If the feasibility set is empty (e.g., active set has fewer assets than required for full investment under per-name caps), the projector falls back to equal-weight among active assets. [UNRESOLVED: exact fallback rule]
[DESIGN NOTE]  Using a differentiable projection ensures that constraint enforcement does not block gradient flow. The agent learns to produce w_pre values that are "close" to feasible, reducing the economic cost of projection over training.
4.6  The Distinction Between w_pre and w_exec
[DESIGN NOTE]  The pre-projection policy entropy is used for SAC temperature tuning because it represents the true stochasticity of the agent's decision-making. The projection is deterministic and does not add or remove entropy ΓÇö it only enforces feasibility. Tracking a counterfactual NAV series using w_pre (without projection) provides a diagnostic measure of the economic cost of the constraint set.

5.1  Decision / Execution Timeline

5.2  Weekly Rebalance Mechanics
At each rebalance date d_t, the agent receives obs_t and produces new target weights w_exec_t.
The difference between w_exec_t and the previous executed weights w_exec_{t-1} determines the trade list.
Trades are converted to dollar amounts using the current NAV: trade_dollars_i = (w_exec_t_i - w_exec_{t-1,i}) ├ù NAV_t.
Trades execute at the open price of d_{t+1}.
Transaction costs are deducted from NAV immediately upon execution (┬º5.4).
5.3  NAV Evolution
The portfolio NAV evolves on a weekly close-to-close basis. Between two consecutive rebalance dates (d_t and d_{t+1}):
NAV_{t+1}  =  NAV_t  ├ù  (1 + r_port_t)  ├ù  (1 - cost_t)
where:  r_port_t  = ╬ú_i  w_exec_t_i ├ù (close_{t+1,i} / close_{t,i} - 1)
                   (close-to-close return of the executed portfolio)
        cost_t    = total transaction costs as fraction of NAV (┬º5.4)
Positions drift intra-week according to individual security returns but are not rebalanced until the next decision point.
The QQQ benchmark NAV is tracked on the same weekly cadence for excess return computation.
NAV is initialized to 1.0 at the start of each episode (┬º5.6).
5.4  Transaction Cost Model
Transaction costs are computed per asset per rebalance step. The total cost for trading asset i at time t is:
total_cost(i,t)  =  |trade_dollars(i,t)| / 10,000
            ├ù [ 1.0
                + M(i,t) ├ù 2.0 ├ù (ADV_median,t / ADV(i,t))^0.3 ├ù max(1.0, ╧â(i,t) / 0.20)
                + M(i,t) ├ù 10 ├ù (|trade_dollars(i,t)| / ADV(i,t))^0.5 ├ù ╧â(i,t) / 0.20
                + 1.5 ├ù ╧â_gap(i,t) ├ù 0.7979
              ]
The four terms inside the brackets represent four cost components, each expressed in basis points (the outer division by 10,000 converts to a decimal fraction of NAV):
Term 1 ΓÇö Commission: 1.0
A flat 1.0 bps commission applied to all trades regardless of size or liquidity.
Term 2 ΓÇö Bid-Ask Spread: M(i,t) ├ù 2.0 ├ù (ADV_median,t / ADV(i,t))^0.3 ├ù max(1.0, ╧â(i,t) / 0.20)
M(i,t): liquidity/market-conditions multiplier for asset i at time t.
(ADV_median,t / ADV(i,t))^0.3: relative liquidity factor. Less liquid assets (low ADV relative to median) incur higher spread costs. The 0.3 exponent moderates the sensitivity.
max(1.0, ╧â(i,t) / 0.20): volatility scaling. Assets more volatile than the 20% annualized baseline incur proportionally wider spreads; the floor of 1.0 applies to low-volatility assets.
╧â(i,t) lookback window: 52 weeks
ADV(i,t)L 63 trading days
ADV_median,t: 63 trading days
Term 3 ΓÇö Market Impact: M(i,t) ├ù 10 ├ù (|trade_dollars(i,t)| / ADV(i,t))^0.5 ├ù ╧â(i,t) / 0.20
(|trade_dollars(i,t)| / ADV(i,t))^0.5: square-root participation rate model ΓÇö a standard empirical approximation of price impact.
╧â(i,t) / 0.20: volatility normalization; higher-vol assets have proportionally greater impact.
The coefficient 10 sets the overall magnitude of the impact term.
M(i,t) = max(1.0, VIX_t /20)
Term 4 ΓÇö Gap / Overnight Risk: 1.5 ├ù ╧â_gap(i,t) ├ù 0.7979
╧â_gap(i,t): overnight gap volatility for asset i (realized standard deviation of open-vs-prior-close gaps over a trailing causal window).
0.7979: the constant ΓêÜ(2/╧Ç), which converts the half-normal mean absolute deviation to the standard deviation scale.
This term captures the risk of adverse price moves between the decision close and the execution open.
╧â_gap(i,t): 52 weeks
Total portfolio cost for the step:
cost_t  =  ╬ú_i  total_cost(i,t)  /  NAV_t
All windows for ╧â(i,t), ╧â_gap(i,t), ADV(i,t), and ADV_median,t are trailing causal windows ΓÇö no future data is used.
[DESIGN NOTE]  The square-root impact model (Term 3) is the standard Almgren-Chriss empirical form widely used in institutional trading cost estimation. The spread model (Term 2) uses a sublinear ADV ratio to capture that less-liquid names have wider spreads but that the relationship is concave. The gap term (Term 4) is the primary reason execution happens at open rather than at close ΓÇö this cost is only realized on execution-date opens and must be estimated from historical overnight gap volatility.
5.5  Benchmark Tracking (QQQ)
A QQQ NAV series is maintained in parallel with the portfolio NAV on the same weekly close-to-close cadence.
r_QQQ_t = QQQ adjusted close return from d_t to d_{t+1}.
The benchmark is used both in the reward function (excess return, MAR computation ΓÇö ┬º6) and in all evaluation metrics (┬º9).
QQQ data is sourced from daily_bars.parquet using the QQQ security_id.
5.6  Episode Initialization, Reset, and Termination
5.6.1  Initialization / Reset
NAV_0 = 1.0
Initial portfolio weights: w_exec_0 = 0 (100% cash; no holdings at start of episode)
All rolling statistics (downside deviation window, reward normalizer, etc.) are zeroed on reset.
Environment randomness (e.g., exploration noise seed) is reseeded deterministically per run/fold/seed index.
The first observation is formed at the first valid rebalance date within the training period that has sufficient lookback history (ΓëÑ L weeks of bar data available).
5.6.2  Termination Conditions
End of trading calendar for the fold's training segment
End of the walk-forward fold's training date range
Inability to form a valid observation window (insufficient lookback data)
On termination, the done flag is set to True for that transition and stored in the replay buffer.
5.7  Forced Liquidation Mechanics and Cost Interaction
Forced liquidations are triggered by three conditions:
NDX removal: asset exits the index per the membership snapshot at t. The environment zeroes that asset's mask entry and forces w_exec_t_i = 0 via the ConstraintProjector at next rebalance.
Missing Data in Temporal Window: missing_L[i] > = 2 
Missing_L[i] = # of trading days with missing price inside trailing 60 day temporal window  
Missing Consecutive Trading Days: streak_missing[i] >= 3
Streak_missing[i] = # of consecutive trading days with missing price ending at or before decision date
Forced liquidation mechanics:
Decision is made at close of d_t (detection date); execution happens at open of d_{t+1}.
The full transaction cost model (┬º5.4) is applied to forced-liquidation trades ΓÇö they are not cost-free.
Forced liquidation events are logged (forced_liquidation_flag, notional, count ΓÇö ┬º10.2).
Diagnostic: the counterfactual w_pre NAV (┬º4.6) also reflects forced liquidations since they are hard constraints.
Part 6: Reward Function
6.1  Complete Reward Formula
The per-step reward at week t is a five-term expression:
r_t  =  (e_t / ╧â_mkt,t)
        ΓêÆ ╬╗_slow  ├ù ╧â_t
        ΓêÆ ╬╗_tail  ├ù max(0,  ΓêÆe_t / ╧â_mkt,t)┬▓
        ΓêÆ ╬╗_cost  ├ù costs_t
        ΓêÆ ╬╗_cv    ├ù violations_t
where every variable is defined as:
[DESIGN NOTE]  Dividing the excess return by ╧â_mkt,t rather than using a raw return signal achieves two things: (1) it scales the reward consistently across high- and low-volatility market regimes, preventing the agent from being over- or under-incentivized based on ambient market conditions; and (2) it implicitly targets a Sharpe/Sortino-like objective without requiring explicit ratio computation in the reward. The tail penalty term (Term 3) is distinct from a symmetric volatility penalty ΓÇö it uses max(0, ┬╖) to penalize only negative normalized excess returns, creating an asymmetric loss surface that mirrors the Sortino ratio's focus on downside risk.
6.2  Reward Term Definitions and Interactions
Term 1 ΓÇö Market-Adjusted Excess Return: e_t / ╧â_mkt,t
e_t      =  r_port_t ΓêÆ r_QQQ_t
╧â_mkt,t  =  rolling_std(r_QQQ_{tΓêÆW_mkt : t})   (causal window, length w_mkt [13 weeks])
This is the reward's primary optimization target. Higher excess return over QQQ, normalized by current market volatility, yields a higher reward. Costs reduce r_port_t and therefore reduce this term (costs also enter explicitly via Term 4).
Term 2 ΓÇö Slow Volatility Penalty: ╬╗_slow ├ù ╧â_t
╧â_t  =  rolling_std(r_port_{tΓêÆW_vol : t})   (causal window, length W_vol [52 weeks])
Penalizes the portfolio's own return volatility. This discourages strategies that achieve positive excess return by taking on excessive absolute risk. "Slow" refers to a longer rolling window that smooths short-term volatility spikes.
Term 3 ΓÇö Quadratic Tail Penalty: ╬╗_tail ├ù max(0, ΓêÆe_t / ╧â_mkt,t)┬▓
tail_penalty_t  =  max(0,  ΓêÆ(r_port_t ΓêÆ r_QQQ_t) / ╧â_mkt,t)┬▓
This term is zero when the portfolio beats or matches QQQ. When the portfolio underperforms QQQ, it activates and grows quadratically with the magnitude of underperformance (on a market-normalized scale). This is analogous to a one-sided L2 penalty on benchmark-relative drawdown.
Term 4 ΓÇö Explicit Cost Penalty: ╬╗_cost ├ù costs_t
costs_t  =  ╬ú_i  total_cost(i,t)  /  NAV_t   (from ┬º5.4)
Transaction costs are penalized explicitly in the reward in addition to reducing r_port_t in Term 1. This double-counting is intentional: it gives the agent a stronger direct gradient signal to reduce turnover, beyond the implicit signal already embedded in the net return.
[DESIGN NOTE]  The double-counting of costs is intentional. Costs enter the reward twice: implicitly through r_port_t (net return after costs, reducing Term 1) and explicitly through ╬╗_cost ├ù costs_t (Term 4). These signals serve distinct roles. The implicit signal teaches the agent that high turnover degrades long-run performance, but it is weak relative to weekly return variance (costs are typically 5ΓÇô10 bps vs. ┬▒100ΓÇô200 bps weekly return swings) and provides poor credit assignment ΓÇö the agent cannot reliably attribute lower returns to trading costs vs. poor stock selection. The explicit ╬╗_cost term creates a direct, labeled gradient signal attributing cost to the specific step in which it was incurred. This is standard reward shaping practice in trading RL systems. The primary calibration risk is ╬╗_cost being set too high, causing pathological trading aversion. Monitor cost_fraction_of_gross_pnl (costs_t / |e_t|) during training: if gross alpha is healthy but net performance is suppressed, reduce ╬╗_cost; if the agent over-trades freely, increase it.

violations_t captures soft constraint breaches. Hard constraints (long-only, full investment, per-name cap, sector cap) are enforced deterministically by the ConstraintProjector and never appear in the reward. This term is likely a diagnostic soft penalty for near-cap approaches or other secondary constraints.

7.3  Ticker and Sector Embedding Design
Ticker embeddings: nn.Embedding(num_tickers, D_ticker) keyed by security_id. D_ticker = 32. Each ticker in the universe gets a distinct learnable vector.

7.4  TCN Design
The Temporal Convolutional Network encodes each asset's L-week feature history into a fixed-size representation.
Receptive field analysis: the full receptive field of the TCN must span at least L weeks to utilize the entire lookback window. Verify: 1 + (kernel_size - 1) ├ù (2^tcn_levels - 1) ΓëÑ L.
[DESIGN NOTE]  SiLU is used instead of ReLU because SiLU has a smooth, non-zero gradient everywhere and empirically outperforms ReLU on smooth financial time-series data. It provides better gradient flow through deep temporal stacks and avoids the dying-ReLU problem.

7.6  Pooling and Aggregation Strategy
Mean pooling: pool the attention output attn_out over active assets only (using mask_t to exclude inactive slots). Result: one global vector of shape [D_attn].

Learned attention pooling summary (query-based)

7.7  Actor Head
The actor head maps asset_repr and g_t to per-asset logits, then applies noise injection and masking:
Architecture: MLP with 128 hidden dimensions, SiLU activations, applied per-asset independently (shared weights across the K_max axis).
Input: asset_repr[i] for each slot i; g_t is typically absorbed into asset_repr before this point.
Output: logits[i] for each i Γêê {0, ..., K_maxΓêÆ1}; a scalar per asset.
Masking: logits[mask_t == 0] ΓåÉ ΓêÆ1e9 before softmax and before noise injection.
Noise injection: logistic-normal noise in logit space (┬º4.4 Step 3).
Softmax ΓåÆ w_pre: standard softmax over the unmasked logits produces pre-projection weights summing to 1.
Log-prob: log ╧Ç(a_pre | s_t) is computed from the pre-projection logistic-normal distribution parameterized by the masked logits.
7.8  Critic Head (Distributional)
Two independent twin critic networks Q1, Q2 produce distributional Q-value estimates via quantile regression:
Architecture: MLP with 256 hidden dimensions, SiLU activations.
Input: concatenation of asset_repr (pooled masked mean over assets), g_t, and action a_pre.
Mean_pool(attn_out) and attn_pool(attn_out) computed and concatenated into state_summary Γêê [D_pool]
critic_input = concate(state_summary, apre) with shape [Dpool, Kmax]
critic_input fed into critic MLP
Output: N_quantiles scalar values q╠é_╧ä for ╧ä Γêê {1/(2N), 3/(2N), ..., (2NΓêÆ1)/(2N)} (fixed quantile levels).
N_quantiles = 32
Quantile Huber loss: the standard distributional TD loss using the pinball (asymmetric Huber) loss across quantile pairs.
Twin aggregation: the critic target uses the minimum of Q1 and Q2 expectations to prevent overestimation.

Part 8: SAC Training Loop
8.1  SAC Objectives (Full Math)
8.1.1  Critic Loss
For each critic i Γêê {1, 2}:
L_Q_i  =  E_{(s,a,R_n,s_n,╬│^n) ~ B}  [  QR-Huber( Q_target, q╠é_╧ä_i(s, a_pre) )  ]
QR-Huber(target, pred) = (1/N┬▓) ╬ú_j ╬ú_k  |╧ä_j - 1(target - pred_k < 0)| ┬╖ L_╬┤(target - pred_k)
where L_╬┤ is the Huber loss with threshold ╬┤,
      ╧ä_j are the fixed quantile levels,
      the sum is over all N quantile pairs (j = target quantiles, k = predicted quantiles)
Q_target  =  R_n  +  ╬│^n ┬╖ (1 - done_n) ┬╖ min(Q1_targ, Q2_targ)(s_n, ├ú_n)
             where  ├ú_n ~ ╧Ç(┬╖ | s_n)
             and    Q1_targ, Q2_targ are the Polyak-averaged target critics
8.1.2  Policy (Actor) Loss
L_╧Ç  =  E_{s ~ B,  a_pre ~ ╧Ç(┬╖|s)}  [  ╬▒ ┬╖ log ╧Ç(a_pre | s)  ΓêÆ  min(Q1(s, a_pre), Q2(s, a_pre))  ]
where:  a_pre is sampled using the reparameterization trick (noise in logit space)
        log ╧Ç(a_pre | s) is the log-prob of a_pre under the pre-projection distribution
        ╬▒ is the current temperature (detached from the alpha loss computation)
        min(Q1, Q2) uses the online (not target) critics
        Entropy is computed from the pre-projection policy only (not post-projection)
8.1.3  Temperature (Alpha) Loss
L_╬▒  =  E_{s ~ B,  a_pre ~ ╧Ç(┬╖|s)}  [  ΓêÆlog(╬▒) ┬╖ ( log ╧Ç(a_pre | s)  +  H_target )  ]
Equivalently:  L_╬▒  =  ΓêÆ╬▒ ┬╖ ( H_current  ΓêÆ  H_target )
where:  H_target = target entropy (K-dependent formula ΓÇö ┬º8.8)
        H_current = mean entropy of the current policy over the batch
        Optimization is over log(╬▒), which is clamped to [log(alpha_min), log(alpha_max)]
8.2  Target Q Computation with n-Step Returns
The target Q is computed using n-step returns to reduce variance and propagate reward signal faster. The n-step return stored in the replay buffer is:
R_n  =  ╬ú_{k=0}^{n_stepΓêÆ1}  ╬│^k ┬╖ r_{t+k}
╬│^n  =  ╬│^{n_step}  (stored per transition)
done_n  =  1  if any  done_{t+k} = True  for k Γêê {0, ..., n_stepΓêÆ1}  else 0
Q_target(s_t, a_pre_t)  =  R_n  +  ╬│^n ┬╖ (1 ΓêÆ done_n) ┬╖ V_soft(s_{t+n_step})
V_soft(s)  =  E_{├ú ~ ╧Ç}[ min(Q1_targ(s,├ú), Q2_targ(s,├ú))  ΓêÆ  ╬▒ ┬╖ log ╧Ç(├ú | s) ]
n_step = 4 (4-week horizon for n-step returns).
n-step returns must NOT cross episode boundaries. If the episode terminates before n_step steps, done_n = 1 and R_n is truncated at the episode end.
n-step returns must NOT cross the warmup boundary (see ┬º8.6). The last n_step ΓêÆ 1 = 3 warmup transitions (indices 49, 50, 51 of a 52-step warmup) are dropped from the replay buffer to prevent n-step contamination.
n-step fields (R_n, ╬│^n, done_n) are computed and stored at the time of transition insertion into the buffer.
8.3  Replay Buffer Design
8.3.1  What Is Stored Per Transition
Note: the raw observation tensors (x_t, g_t) are NOT stored in the buffer. They are reconstructed on demand from t_idx using the precomputed features panel. This reduces memory footprint at the cost of some I/O.
8.3.2  Capacity and Structure
Replay capacity: 800 transitions total (from 3 parallel episodes per fold, each contributing ~267 transitions from a 5-year training window at ~52 weeks/year).
Storage format: fixed-size circular buffer padded to K_max for all variable-K tensors.
Running statistics maintained as buffer metadata, updated on every insertion: reward_std (scalar), per_feature_std (vector of length F). Used for transition augmentation (┬º8.4).
8.3.3  Sampling Scheme
Default: Exponential Recency Weighting. Each transition is assigned a sampling weight proportional to exp(ΓêÆ╬╗_recency ├ù age), where age is measured in calendar time from the transition's t_idx to the most recent transition in the buffer.
w_i  =  exp(  ΓêÆln(2) / (half_life_weeks)  ├ù  (t_max ΓêÆ t_idx_i)  )
half_life_weeks  =  recency_half_life_years ├ù 52  =  3 ├ù 52  =  156  weeks
Sampling probability: P(i) = w_i / ╬ú_j w_j
Recency is computed from the transition's calendar date (t_idx), NOT from insertion order. This ensures transitions from different episodes in the same time period receive equal recency weight.
Alternative samplers supported but not default: Uniform, Recent Window.
Prioritized Experience Replay (PER): NOT used in Project Apex.
[DESIGN NOTE]  Exponential recency weighting biases sampling toward more recent experience, which is more relevant under non-stationary market conditions, while still retaining older transitions for stability. Using calendar date (not insertion order) makes the recency weight semantically meaningful across the multi-episode collection protocol.
8.4  Transition Augmentation
Two augmentations are applied every time a transition is drawn from the buffer during training:
8.4.1  Reward Noise
r_aug  =  r_stored  +  ╬╡_r
╬╡_r ~ N(0,  (aug_reward_noise_factor ├ù buffer_reward_std)┬▓)
aug_reward_noise_factor = 0.01
buffer_reward_std = running std of all rewards in the buffer (updated on insertion)
8.4.2  Observation Feature Noise
x_aug[t, k, f]  =  x_stored[t, k, f]  +  ╬╡_obs[f]
╬╡_obs[f] ~ N(0,  (aug_obs_noise_factor ├ù per_feature_std[f])┬▓)
aug_obs_noise_factor = 0.015
per_feature_std[f] = running std of feature f across all active-slot entries in buffer
Noise is resampled independently every time a transition is drawn (not stored).
Augmentation is applied ONLY to the critic training path. The actor computation uses the clean (un-augmented) features. This is critical: augmenting the actor path could corrupt log-probability computations and distort the entropy estimate.
Running statistics (buffer_reward_std, per_feature_std) are updated at each transition insertion, not at sampling time.
[DESIGN NOTE]  Transition augmentation acts as a form of data regularization, reducing overfitting to specific realized returns and feature patterns. Applying it only to the critic (not actor) ensures log-prob computations for entropy remain accurate.
8.5  Multi-Episode Collection Strategy
Per fold: 3 independent episodes are run through the same training date range.
Episodes differ only in their stochastic logit-noise realization (different random seeds for the logistic-normal exploration noise). All other aspects (environment data, normalization statistics, feature pipeline) are identical.
All 3 episodes run SEQUENTIALLY to completion before any gradient updates begin. The replay buffer is fully populated with 3 episodes of experience before training starts.
This is NOT online learning: the agent does not update its policy mid-episode.
[DESIGN NOTE]  Running multiple episodes with different exploration seeds before training ensures the replay buffer contains diverse exploration coverage. This reduces the risk that the policy overfits to a single trajectory realization, especially important for an off-policy agent on short financial time series.
8.6  Warmup Strategy
warmup_steps = 52 (approximately 1 year of weekly steps).
During warmup, actions are generated by sampling random logits from a standard normal distribution (not the policy network) and applying the deterministic projection. This produces random-but-feasible portfolios.
Warmup transitions ARE stored in the replay buffer (flagged with warmup_flag = 1).
Exclusion rule: once the buffer contains ΓëÑ 128 policy-generated transitions (warmup_flag = 0), warmup transitions are excluded from sampling. They remain in the buffer but receive zero sampling weight.
n-step boundary rule: the last n_step ΓêÆ 1 = 3 warmup transitions (steps 49, 50, 51 of a 52-step warmup) are DROPPED entirely from the buffer (not stored) to prevent n-step returns from spanning the warmup-to-policy boundary.
[DESIGN NOTE]  The warmup period populates the replay buffer with diverse, feasible portfolio transitions before any gradient updates occur. This prevents the critic from being initialized on a degenerate set of experiences. The 52-step warmup corresponds to a full calendar year, providing broad coverage of market conditions at fold start.
8.7  Update Schedule
Per update step (critic updates every step; actor and alpha every policy_delay steps):
Sample batch B of batch_size = 64 transitions from replay (with recency weighting).
Apply transition augmentation (┬º8.4) to the batch.
Compute Q_target using target critics and n-step fields from batch.
Update Q1 and Q2 critics: compute L_Q_i for each; backward; clip grad to grad_clip_critic = 1.0; step critic optimizer.
Every policy_delay = 2 steps: update actor (L_╧Ç) and alpha (L_╬▒); clip actor grad to grad_clip_actor = 5.0; step actor and alpha optimizers.
After every critic update: Polyak-update target networks (┬º8.10).
8.8  Entropy Tuning (Auto-Alpha)
SAC uses automatic temperature tuning to maintain a target entropy level. The target entropy is K-dependent to account for variable portfolio size:
H_target  =  ΓêÆln(K_active)  ├ù  scale_factor
Rationale: with K_active active assets, a uniform distribution has entropy ln(K_active).
Four unit tests for alpha tuning stability must be implemented (┬º11.1):
Test 1: verify log-prob is correctly computed for a known action.
Test 2: verify alpha loss gradient has correct sign.
Test 3: verify alpha converges to alpha_max when policy entropy is below target.
Test 4: verify alpha converges toward alpha_min when policy entropy exceeds target.
8.9  Optimizer Configuration
LR scheduling: no LR scheduler is active by default. If performance peaks early and then degrades, implement cosine annealing with warm restart.
Weight decay: NOT applied to embedding parameters (TickerEmbedding, SectorEmbedding) even when encoder uses AdamW with wd=1e-4. Embeddings are in a separate parameter group with wd=0.0.
Determinism: all random seeds are fixed. CUDA deterministic operations are enforced (via torch.use_deterministic_algorithms(True) or equivalent).

Part 9: Evaluation Framework
9.1  Walk-Forward Fold Design
Project Apex uses 8 expanding-window walk-forward folds. Each fold has a training period (in-sample, IS) and a test period (out-of-sample, OOS). An embargo of 4 weeks separates training end from test start to prevent leakage via n-step returns.
Embargo mechanics: the last embargo_weeks = 4 weeks of training data are excluded from the replay buffer at fold training time. This prevents n-step returns (n_step = 4) from incorporating future test-period returns.
Valid training indices:  t_idx  Γëñ  train_end_idx  ΓêÆ  embargo_weeks
Valid bootstrap test:   t_boot  Γëñ  train_end_idx  AND  t_boot  <  test_start_idx
N_steps_dropped_due_to_embargo  =  embargo_weeks  =  4
N_steps_dropped_due_to_insufficient_lookback  =  L  (first L weeks of training have no full history)
Exact purged/dropped dates per fold are recorded in the fold metadata log (┬º10.3).
9.2  Leakage Validation Tests
After each fold training, the following leakage checks must pass before OOS evaluation is run:
Temporal: assert that all feature computation windows for step t use only data with index Γëñ t_idx.
Normalizer: assert that normalization statistics were fitted only on training-period data.
Membership: assert that membership snapshots at t_idx use backward-fill only (as-of rule).
Embargo: assert that no training transition has t_idx within the embargo window.
n-step boundary: assert no n-step return spans the trainingΓÇôtest boundary.

9.5  Confidence Intervals (Block Bootstrap)
Procedure:
  1. Concatenate all OOS weekly excess return series across folds into one series of length T.
  2. Block length  b  =  floor(T^{1/3})   (typically 8ΓÇô12 weeks in practice).
  3. Resample  bootstrap_resamples = 10,000  times by drawing blocks with replacement.
  4. For each bootstrap sample, compute the metric (e.g., Excess CAGR).
  5. Report the 2.5th and 97.5th percentiles as the 95% confidence interval.
Pass criterion: CI_lower(Excess CAGR) > 0%
                CI_lower(Sortino) > QQQ_Sortino
[DESIGN NOTE]  Moving block bootstrap preserves the temporal autocorrelation structure of weekly returns, which is critical for financial return series that exhibit momentum, mean-reversion, and volatility clustering. Non-overlapping block bootstrap would underestimate variance; this method provides better coverage.

12.2  Guardrails at Inference Time
The following guardrails must be enforced at every inference step:
Feasibility check: after ConstraintProjector, assert all constraints are satisfied (┬º1.3). If any violation is detected, halt and alert.
Mask integrity: assert mask_leak_mass == 0 (no weight on non-members or inactive assets).
Universe validity: verify the NDX membership snapshot used at decision time is the most recent as-of snapshot (┬º2.5).
Stale data guard: if any active asset has not received a price update within the expected window, flag as missing data (┬º12.3).
NAV plausibility: assert NAV change between steps is within a plausible range; large unexplained NAV jumps should trigger an alert.
12.3  Missing Data Handling at Inference
If an active asset has a missing adjusted close on the decision date: freeze the previous position weight for that asset (do not reduce or liquidate immediately).
If missingness persists beyond the allowed threshold, flag the asset for forced liquidation at the next rebalance.
If the feature window for an active asset cannot be constructed due to data gaps, the asset is treated as non-tradeable (mask set to 0) for that step.
12.4  Paper Trading Considerations
At paper trading start, initialize the portfolio to weights equal to weights from most recent warmup step
Transaction cost model: apply the same model as training (┬º5.4) for simulation purposes. Real execution costs may differ; calibrate periodically.
Universe updates: fetch NDX membership snapshots from the data provider on the morning of each rebalance date (Monday open), before generating signals.
Price data: use adjusted prices from the data provider; verify adjustment factors are up-to-date.
Signal generation cadence: generate new w_exec weights at the close of each Monday (or first trading day of week). Trades execute at Tuesday open.
Part 13: Unresolved Items and Known Risks
13.1  SoT "To Decide Later" Items
LR scheduling: the SoT explicitly defers this decision, noting "implement cosine annealing if performance peaks early and degrades." This should be resolved after initial training runs.
updates_per_step range 25ΓÇô35: the SoT notes this as an option if convergence is slow. The default of 20 should be validated empirically in early fold runs before increasing.

Projection economic cost not rewarded | LOW | The counterfactual w_pre NAV (┬º4.6) is tracked diagnostically but the projection cost is not explicitly penalized. Sector adjacency bias as hyperparameter | MEDIUM | If the sector adjacency bias is a learned parameter and the training periods are short, it may overfit to particular sector dynamics of that era. Consider fixing it (binary 0/1 indicator) and learning scale as a scalar.
